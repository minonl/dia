# 生态定位：我们落在哪，接谁、不接谁

> 日期 2026-10-28。
> 一句话：**dia 不做通道、不做运行时、不做记忆产品；dia 做"进化的控制面"——观测、审计、基准、门禁。**
> 长期形态（superagent / agent-team 工厂、fleet 对接）见 [`vision.md`](vision.md)；本文的"不做"边界仍然有效。
> 通道用 dws-hub，执行用 dsh/opencode，其他 agent 只当可选后端。

---

## 1. 各家真正擅长什么（不是宣传语）

| 工具 | 真正擅长 | 代价 / 风险 | 证据 |
|---|---|---|---|
| **dws-hub**（本地） | 钉钉 Stream 长连接、消息落盘、launchd 常驻 | 只覆盖钉钉；需桥接层 | 本机 launchd + plist |
| **dsh** | 插件树（Cordis）、事件溯源会话、沙箱/审批/断点、ACP | 生态小、文档少 | 本机源码 |
| **opencode v2** | 会话 daemon、project/location 作用域、TUI/客户端生态、SDK | 单点共享 daemon、版本断代 | 本机 + 官方文档 |
| **OpenClaw** | **多通道接入**（WhatsApp/Telegram/Slack/Discord…）、常驻 gateway、automations | 重；供应链事故（ClawHavoc）；CVE-2026-25253 | 取证文档 |
| **Hermes** | **长期记忆 + 自建技能闭环**（3575 字符硬顶、Curator） | 重；两套执行路径；CVE 未修复、厂商未回应 | 取证文档 |
| **Pi** | **极简 coding harness**：核心小、扩展优先、TS 原生、prompt cache、ACP（`pi-acp`） | 无内建沙箱/审批；fail-open；无通道 | 取证文档 |

**Pi 的好点**（回答你的问题）：不是记忆，也不是通道，而是**"薄内核 + 扩展"**：
- 核心极小，能力靠 extension 拼；
- 同进程扩展（灵活但危险）；
- 模型目录 + prompt cache 做得细；
- `pi-acp` 让它能被 ACP 驱动。
它适合当**编码执行体**，不适合当常驻消息入口。

---

## 2. 常驻入口：用 dws-hub，不用别的

| 方案 | 能给你什么 | 代价 | 结论 |
|---|---|---|---|
| **dws-hub + launchd + dsh/opencode** | 本地、已在跑、可控、可审计 | 需要写一个 bridge（消息→任务→回复） | **推荐** |
| OpenClaw | 多通道开箱即用 | 引入第二套运行时/技能/安全面 | 不现在接 |
| Hermes | 通道 + 记忆 + 技能 | 同上，且有未修复 CVE | 只做研究参考 |
| Pi | 极简编码 | 无通道、无审批 | 可当编码后端（ACP） |

**推荐链路**：

```
钉钉消息 → dws-hub（已有长连接）→ inbox 落盘
        → dia bridge（launchd/定时或事件触发）
        → 任务（ledger）+ 审计（dia run）
        → 执行后端：dsh headless（批处理）/ opencode 会话（交互）
        → 草稿回复（draft-only）→ 人工确认 → dws 发送
```

**为什么不直接用 OpenClaw 的 gateway**：
- 它的价值是"多通道"，我们只需要钉钉一条；
- 它自带运行时/技能/记忆，会和 dia 的策略层重复；
- 安全面大（CVE + 供应链），与我们"审计优先"冲突。

---

## 3. dia 的生态位

```
通道（dws-hub）→ 控制面（dia）→ 执行体（dsh/opencode/ACP 后端）→ 证据/基准/知识
```

dia 只做四件事：
1. **观测与记录**：会话、工具、失败、成本（不复制真相，只索引）。
2. **审计与止血**：seam 上的判定、冻结、豁免、证据。
3. **基准与漂移**：ModelSpec、baseline、事故 canary、观察名单。
4. **门禁与进化**：判据、独立验证、假设台账、回滚。

**不做**：通道实现、会话运行时、模型服务、技能市场、记忆产品。

---

## 4. 未来对接策略：适配，不吞并

| 对象 | 怎么接 | 前提 |
|---|---|---|
| OpenClaw | 当 **ACP 端点/通道适配器**；只读收消息，草稿回复 | 不引入其技能市场；审计覆盖其工具调用（做不到就只观测） |
| Hermes | 当 **ACP 端点**；只借鉴记忆/技能机制，不接管 | 版本固定；CVE 未修复前不跑高权限 |
| Pi | 当 **编码执行体**（`pi-acp`） | 只跑隔离任务；无审批，需外层 gate |
| dsh | 主执行体 | 已定 |
| opencode | 交互式会话后端 | 已定 |

**接入判据（任一条不满足就不接）**：
1. 能被 ACP 或 CLI 黑盒驱动；
2. 工具调用可被审计（至少可观测）；
3. 版本可钉、可回滚；
4. 不要求我们复制它的记忆/技能体系。

---

## 5. 一句话回答

- **常驻启动**：用 **dws-hub + launchd + dsh/opencode**，不引入 OpenClaw/Hermes/Pi。
- **会话转发**：dws-hub 负责通道，dia 负责策略与证据；转发是 bridge 的活，不是 agent 的活。
- **生态位**：**个人进化的控制面**，不是又一个 agent 框架。
- **未来对接**：只做 ACP/CLI 适配器，不吞并它们的运行时。
