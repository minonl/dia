# 进化：dia 的第一性定位

> 日期 2026-10-28。本文不是功能清单，是**过程定义**。
> 生态位（框架/插件/ACP）是自然落点，不是目标；能力只有在过程需要时才被引入。

---

## 1. 一句话

> dia 维护的不是"一个 agent"，而是一个**可观测、可回溯、可自我调整的进化过程**。
> 人和电子脑是这个过程的两个引擎，长期磨合的产物才是产出。

判据不是"功能做完了"，而是：**下一次同类问题，系统是否比上次少犯一次错、少花一次时间、少一次人工介入。**

---

## 2. 循环（七段，缺一段就不叫进化）

```
        ┌────────────── 意图锚点 Intent（人工，只读）──────────────┐
        │                                                          │
        ▼                                                          │
   观测 Observe ──> 记录 Record ──> 蒸馏 Distill ──> 评审 Review ──┤
        ▲                                              │           │
        │                                              ▼           │
   调整 Adjust <── 度量 Measure <── 尝试 Try <──────────┘           │
        │                                                          │
        └────────────── 历史锚点 History（只追加）──────────────────┘
```

| 段 | 做什么 | 产物 | 归属 |
|---|---|---|---|
| **观测** | 会话、失败、用户纠正、外部生态变化 | `observations`（原始，脱敏） | agent |
| **记录** | 归一为 episode；不可变 | `episodes.jsonl` | agent |
| **蒸馏** | 从 episode 提候选经验/假设，**不是结论** | `candidates` / `hypotheses` | agent 起草 |
| **评审** | 双引擎：证据分级 + 对抗 + 裁决 | `review` 记录 | 人 + agent |
| **尝试** | 最小改动/实验，可回滚 | `experiments` / `evo-*` | agent 执行 |
| **度量** | 指标 + 回归 + 意图漂移 | `metrics` | 脚本 |
| **调整** | 采纳/回滚/归档；写回历史 | `history` | 人批 |

**两个锚点**：
- **意图**（为什么做）：人工维护，agent 只读；任何改动与意图冲突 → 必须人工裁决。
- **历史**（发生过什么）：只追加，不覆盖；"铭记历史"不是口号，是**不可变日志 + 可检索**。

## 2.1 V 型协作结构（补充模型）

```
                人（顶端：意图 / 价值 / 裁决 / 停手）
               /                                  \
      下降臂（尝试/探索/试错）          上升臂（请示/汇报/交还决策）
               \                                  /
                谷底：任务目标（可能触底，也可能永远触不到）
```

- **AI 在两臂之间跑线**：下降 = 推进尝试；遇到无法绕开的障碍 = 沿上升臂回到人请示；人给决策后再下降。
- **触底**不是唯一成功：到达某一深度并**记录障碍类型**，也是有效产出。
- **上升不是失败**，是**决策采样**：每次请示都在标注"哪类障碍必须由人裁定"。
- **深度**是连续量（0–100%），不是二元成败；同一任务族的历史深度分布，比"成功/失败"更有信息。

### 2.1.1 多维状态：角色 × 任务图 × 观测效应

V 型是二维投影。真实状态至少是三元组：

```
State = (T, D, O)
  T：任务图（不是任务列表）
  D：深度矩阵 D[观测者][任务节点] ∈ [0,1]
  O：观测事件及其对 T/D 的影响
```

#### 维度一：角色 = 观测角度

| 观测者 | 看到什么 | 常见偏差 |
|---|---|---|
| 人 | 目标价值、外部约束、停手时机 | 低估实现细节的深度 |
| 主 agent | 计划与已完成步骤 | 高估推进（把"做了"当"有效"） |
| 子 agent | 自己负责的分量 | 局部最优、看不到全局权重 |
| 系统/脚本 | 可度量指标 | 只测可测的，漏掉意图 |

**规则**：不取平均。`Δ = max(D[o][t]) - min(D[o][t])`。
对齐优先级 = **`Δ × 该判定的错误成本`**（Horvitz 1999），阈值**预注册**；
**不设拍脑袋的 0.3**（原阈值无文献依据，已撤回）。
另：`Δ≈0` 不能证明"都对"——也可能是**共谋**（Lee & See 2004）；必须配合盲复核。

#### 深度不是标量：按四类功能分别记

Parasuraman/Sheridan/Wickens (2000) 的 types×levels：**信息获取 / 信息分析 / 决策 / 执行**各自定级。
禁止输出单一"深度分"；矩阵必须是 `D[observer][task][function]`。

#### 维度二：任务图（会生长、会消失、会聚合、会发散）

任务不是固定列表，是有生命周期的图：

```yaml
task:   { id, parent, origin, weight, status }
# origin: original | derived | merged | split | observation-induced
# weight: 该节点占目标的比例（可随时间变化）
```

- **新增**：agent 发现的新前提（如"先修 CI 才能发版"）；
- **消失**：前提被证伪、或目标变更；
- **聚合**：其他任务并入（范围变大）；
- **发散**：一个节点裂成多个（范围变大但更清晰）；
- **观测诱发**：因为我们观察/度量而新增的任务（见下）。

**规则**：`派生比 = Σweight(derived + observation-induced) / Σweight(original)`。
派生比持续升高 = 目标在漂移，必须先压缩/收敛，不许继续扩张。

#### 维度三：观测效应（系统自己成为变量）

观测不是免费的：一次度量可能
1. 改变任务图（新增"验证/记录/清理"任务）；
2. 改变深度估计（看到更多细节 → 深度反而下降）；
3. 改变后续行为（被观测者知道被观测）。

因此每次观测都记一条事件：

```yaml
event: { type: observe|add|remove|merge|split|reweight, cause, actor, ts,
         intent_id, judge_id, upstream_artifact_ids,   # provenance（MHC tracing）
         sa_level: L1|L2|L3,                            # 情境意识层级（可选）
         effect: { added: [], removed: [], reweighted: [] } }
```

**规则**：`观测诱发变更率 = 有 effect 的观测 / 总观测`。
过高 → 降低观测频率或改成抽样；否则系统会陷入"为了看清楚而制造更多工作"的循环。

#### 由此新增的指标

| 指标 | 公式 | 用途 |
|---|---|---|
| 观测分歧 Δ | max-min 深度（按任务×功能） | 按 `Δ × 错误成本` 排序对齐 |
| 派生比 | derived+observation-induced 权重 / original 权重 | 升高 = 目标漂移 |
| 任务图 churn | (add+remove+merge+split) / 周 | 过高 = 结构不稳 |
| 观测诱发变更率 | 有 effect 的观测 / 总观测 | 过高 = 观测成本失控 |
| 聚焦熵 | 注意力在各节点上的分布熵 | 过高 = 失焦 |

### 2.1.2 存储原则：不重复存放会话

```
真相层（不归 dia 所有）：
  opencode  session/message/part  →  ~/.local/share/opencode/opencode.db
  dsh       session.v4.jsonl.zstd →  ~/.dsh/sessions/<workspace>/

索引层（dia 所有，可重建）：
  state/events.jsonl     只追加：任务图变更 / 深度上报与复核 / 观测影响 / 决策
  state/index.db         派生索引（FTS/聚合视图），删掉可重建
  state/snapshots/       有期限的完整备份（默认 30 天，只为回放/回填）

引用：raw_ref = {source, session_id, part_id?}
```

**规则**：

1. **不复制 transcript**：dia 只存引用 + 事件；原文永远回源读。
2. **索引可重建**：删除 `index.db` 与 `snapshots/`，能从"源会话 + events"重建出同样的视图（哈希一致）。
3. **备份有期限**：完整备份只为"源被删/升级不兼容"时回放，默认 30 天，到期自动清；它不是事实源。
4. **视图是聚合**：`task_graph` / `depth_matrix` / `Δ` / `derived_ratio` / `obs_effect_rate` 都是事件流上的投影，不单独存事实。

事件 schema（v0）：

```yaml
id: <hash>
ts: ISO
actor: human | agent | subagent | system
type: task.added | task.removed | task.merged | task.split | task.reweighted
    | depth.reported | depth.reviewed
    | observation.effect
    | decision.made
task: { id, parent, origin, weight }
depth: { observer, task, value, basis }
effect: { added: [], removed: [], reweighted: [] }
ref: { source, session, part? }
```

### 2.2 不完整过程也是产出

每次 attempt 记录：`{task, depth, obstacle, decision_needed, human_decision, cost, evidence, judge_version}`。

三类可复用资产：
1. **深度先验**：这类任务通常能到多深、在哪一层卡住；
2. **障碍清单**：哪类障碍必须回人（而不是继续试）；
3. **决策日志**：人当时怎么裁定、依据是什么。

**判据公开（"公示"）**：同一套判据可以对历史 attempt 重新评分——所以旧的失败在新判据下可能变成有效证据。
这也是"铭记历史"的实际用法：不是留着日志，而是**能重打分**。

### 2.3 实例爆炸 → 系统性索引压缩

三层，越往下越贵、越少：

| 层 | 内容 | 保留 | 压缩方式 |
|---|---|---|---|
| **原始** | observations / episodes | TTL 30 天 | 按签名去重 |
| **先验** | 聚类后的深度/障碍先验 | 长期 | 同族 ≥N 触发；保留深度分布 + 代表样例指针 |
| **决策** | 人的裁定与理由 | 永久 | 只追加，不改写 |

压缩后只保留：`签名 / 深度分布 / 障碍类型 / 代表样例指针 / 判据版本`。
目标：存储 O(instances) → O(priors)，检索与决策成本不随实例数线性增长。

## 3. 两个引擎的分工

| | 人脑 | 电子脑 |
|---|---|---|
| 强项 | 意图、价值判断、阈值、承担责任 | 规模观测、一致性检查、快速起草、反复重试 |
| 职责 | 定"为什么"、批"能不能"、裁决冲突 | 做"看见"、"记录"、"提候选"、"跑实验" |
| 失败模式 | **忘记初心**（意图漂移）、疲劳漏看 | **优化代理指标**（刷分）、讨好人类、记忆腐烂 |
| 对策 | 意图锚点 + 定期复核 | 对抗审计 + 独立证据 + 回归门禁 |

**磨合**的定义：不是"人机对话变顺"，而是**同样的判断，第二次比第一次更快、更一致、更有据**。

## 4. 进化指标（不做 productivity 指标）

| 指标 | 定义/公式（必须能从事件算） | 健康信号 |
|---|---|---|
| 观测覆盖率 | 被记录的事件 / 实际发生的事件 | ↑ |
| 经验产出率 | candidates / 100 episodes | 稳定，不追求高 |
| **推翻质量** | `有效推翻 / (有效推翻 + 误报)`；单看推翻率不采纳（防 Goodhart） | 稳定且 >50% |
| 重试成功率 | 失败后重试成功 / 总重试 | ↑ |
| 回归率 | 改动导致旧能力退化 / 总改动 | ↓ |
| **意图漂移** | 与意图锚点冲突的决策数；**意图变更的 actor 必须是人**（agent 写入数 >0 即失败） | 0 |
| 信任度 | 审计通过率、豁免率、冻结次数 | 豁免率 ↓ |
| 人工介入率 | 需要人处理的步骤 / 总步骤 | ↓，但**意图变更 100% 由人发起** |
| **校准** | 自报 vs 盲复核的 ECE / Brier；ICC(2,k) | 替代"深度达成"；盲复核必须异源 |
| 深度达成 | 任务族的四类功能中位深度 | 分开报，不合成单一分数 |
| 请示质量 | 回人的障碍里"必须人裁定"的比例（其余应继续试） | ↑ |
| 部分产物复用率 | 被后续 attempt 引用的失败 attempt / 总失败 | ↑，但需配下游返工率 |
| 压缩比 | 先定义"信息量 vs token"，否则不测 | ↑，但检索命中率不能掉 |
| 检索命中率 | 先验被正确召回 / 总召回请求 | ≥90% |
| 边际深度 | 每次尝试带来的深度增量 | 趋近 0 时应停止/换路 |
| 共谋信号 | ①人推翻"秤"通过结论的次数 ②人回答 agent 问题的平均字数 ③连续无分歧任务数 | ①=0；②≥20 字；③<10 |

> 不进指标的东西：功能数量、代码行数、提交数。
> **规则**：没有对应事件（`core/events.yaml`）与公式的指标，不进表；宁可不测，不测空话。

## 5. 能力引入的规矩（针对"拿来主义"）

**任何外部能力（库、插件、协议、别人的引擎）都先当假设，不当结论。**

引入前必须有一份 **REUSE ADR**（见 `docs/review/reuse-review.md`），至少包含：

1. 主张（我们要复用它做什么）
2. 证据级别（A 源码/官方 / B 官方博客 / C 第三方 / D 传闻）
3. **本地探测结果**（命令 + 输出；没跑就写"未验证"）
4. 失败模式（它坏了/变了/被弃用，我们怎么办）
5. 耦合代价（版本、许可证、维护者数量、退出成本）
6. 裁决：`adopt` / `adapt` / `reject` / `defer`（defer 必须写复查日期）

没有本地探测的复用，只能标 `defer`，**不许进主路径**。

## 4.1 请示与打断（理论约束）

- **请示三件套**：不确定性 / 候选及代价 / 推荐项（Horvitz 1999）。
- **打断预算**：每人每时段上限，超限转异步队列。
- **顶端只保留三类决策**：目标选择、冲突裁决、异常接管。
- **自动化升级时**同步提高人的手动演练配额（Bainbridge 1983 / OOTL）。

## 4.2 共谋（必须可判）

`Δ≈0` 有两种解释：都准，或都错。判别只能靠**盲复核 + 第三方抽检**；
"人推翻秤结论的次数"必须为 0，但该指标**不得进个人考核**（Campbell 定律）。

## 5.1 认知分工：知其然，不知其所以然

- 人负责 **why**：什么值得做、什么算好、什么时候停。
- 电子脑负责 **how**：试、量、记、压缩。
- 系统**不承诺理解因果**，只承诺"可复用的行为先验"；因果解释由人补，或作为假设去验证。
- 这不是缺陷，是分工：**局部优化由机器做，全局意图由人守**。

## 6. 与现有能力的关系（能力是仪器，不是目的）

| 已有/在建 | 在循环里的位置 |
|---|---|
| ingest（会话采集） | 观测 |
| episodes + 脱敏 | 记录 |
| candidates（候选） | 蒸馏的输入 |
| hypotheses（H1–H8） | 蒸馏的产物 / 评审对象 |
| audit / freeze | 信任与边界（度量的一部分） |
| kb（知识库） | 历史锚点的检索面 |
| pkg / render | 把"调整"落到宿主 |
| ACP / 编排 | 让两个引擎能接上，不是目的 |

## 7. 失败判据（什么时候承认定位错了）

1. 连续 4 周，观测覆盖率不升、候选采纳率为 0 → 过程没跑起来。
2. 连续 4 周，人工介入率 100% 且没有下降 → 电子脑没形成能力。
3. 出现"为了用框架而用框架"的功能 → 生态位变成了目的，回到本文 §1。
4. 意图锚点 3 个月没被引用过一次 → 初心已经丢了。
