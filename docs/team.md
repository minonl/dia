# 团队章程：谁来做 dia（开发团队）

> 日期 2026-10-28。
> **2026-10-28 升级**：开发团队执行模式改为**全自动循环**（计划→实现→验证→对抗→修复），**人只在验收阶段介入**；
> 状态机、门禁、验收包见 `docs/team-automation.md`。本文保留角色定义与章程。
> 先区分两层，别混：
> - **产品团队**：dabo 的 9 个角色（大波/点子/爪子/炸毛/秤/记性/管家/信箱/磨爪）——是 agent 产品内部的角色。
> - **开发团队**：做 dia 这个框架的人/agent 分工——本文。

---

## 1. 现状（诚实版）

| 项 | 现状 |
|---|---|
| 固定组员 | **没有**。只有主 agent（我）+ 按需子 agent |
| 角色是否落地 | 产品 9 角色只在文档里；开发角色没有定义 |
| 实际分工 | 我同时做架构/实现/验证；研究、红队用一次性子 agent |
| 最大风险 | **实现者与验证者是同一个人**，自签验收 |

**结论**：现在不是"团队"，是"一个人 + 临时工"。

---

## 2. 建议的固定组员（4 个）

"固定"不等于常驻进程，而是：**每个里程碑必须经过这个角色，且它有明确的输入/输出契约**。

| 角色 | 职责 | 输入 | 输出 | 不许 |
|---|---|---|---|---|
| **主控（人）** | 意图、优先级、裁决、批准 | 设计/证据/风险 | 决策、批准/否决 | 替 agent 写代码/做技术判断 |
| **架构（planner）** | 设计、假设、ADR、拆任务 | 需求/证据 | `docs/*.md`、H 条目、任务拆解 | 写实现、给自己签验收 |
| **实现（builder）** | 代码、测试、文档同步 | 设计与判据 | diff + 测试输出 | 改判据、自签验收 |
| **验证（verifier）** | 独立跑判据、三态结论 | diff + 测试 + 判据 | 验证报告（通过/不通过/无法判定） | 改代码、与实现同上下文 |
| **档案（archivist）** | 证据、依赖、基线、历史 | 验证报告/探针结果 | `deps.yaml`、`baselines/`、决策记录 | 写无日期无判据的裸事实 |

**硬规则**：实现者 ≠ 验证者；验证者不得与实现者共享上下文（独立子 agent，只读 diff + 测试输出）。

---

## 3. 按需组员（3 个，不进固定编制）

| 角色 | 何时启用 | 为什么不做固定 |
|---|---|---|
| **红队（redteam）** | 里程碑评审、合并前、安全相关改动 | 成本高，且需要"陌生视角"，常驻会钝化 |
| **研究（researcher）** | 生态/基准/理论取证 | 项目式任务，完成即解散 |
| **发布（ops）** | 打包、CI、launchd、版本 | 低频，可按阶段启用 |

---

## 4. 工作流（全自动，人只在验收）

```
人给意图
  → 架构：设计 + 可证伪判据 + 拆任务（自动）
  → 实现：代码 + 测试（自动）
  → 验证：独立角色，只读 diff/测试，出三态（自动）
  → 红队：反驳清单（自动）
  → 修复循环（≤3 轮，自动）
  → 验收包 → 人 accept / reject
```

详见 `docs/team-automation.md`。

**门禁**：
1. 没有判据不开工；
2. 没有独立验证不合并；
3. 行为类改动必须人批；
4. 自签验收 = 违规（记入 `security_debt` 同类）。
5. 证据缺失（命令 + 输出）= 无法判定。

---

## 5. 交付物契约（控制上下文成本）

| 角色 | 交付物 | 长度上限 |
|---|---|---|
| 架构 | 设计文档 / ADR | 1 页/决策 |
| 实现 | diff + 测试命令与输出 | diff 原样，输出摘要 |
| 验证 | 三态报告 + 证据 | 半页 |
| 红队 | 反驳清单 | 每条 4 要素 |
| 档案 | 登记行 / 基线 JSON | 结构化，不写散文 |

**原则**：agent 之间只传**结论 + 证据指针**，不传完整会话（避免上下文膨胀）。

---

## 6. 指标（团队自身）

| 指标 | 目标 |
|---|---|
| 自签率（实现者自己签验收） | **0** |
| 独立验证发现的问题数 / 总问题数 | ≥30% |
| 返工率（因判据不清导致） | ↓ |
| 证据缺失的结论数 | 0 |
| 每位固定角色的上下文成本 | 可估算、可上限 |

---

## 7. 与"进化过程"的关系

- 人机两个引擎：人是主控；电子脑内部再分架构/实现/验证/档案。
- V 型：人守顶端；遇到障碍（判据不清、价值冲突）由架构/验证上升请示。
- 团队是**过程的一部分**，不是目的；角色可以增减，但"独立验证"和"人批行为"两条不能省。
